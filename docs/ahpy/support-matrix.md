# aHPy support matrix

The current release envelope is the unpublished
[`preview` contract](release-contract.md): CPython 3.11, HPy 0.9.0, and the
six exact platform/compiler lanes listed there. These feature statuses do not
claim general Cython compatibility. Principal HPy 0.9 and distribution gaps
are summarized in [`known-limitations.md`](known-limitations.md).

Status values:

- **planned**: designed but not implemented;
- **in progress**: implementation exists but has not passed its exit gate;
- **supported**: the documented preview behavior is a user-facing promise and
  all of its required tests and audits pass;
- **partial**: only the written subset is promised and unsupported cases are
  diagnosed without fallback;
- **blocked**: a public external API or unresolved correctness design prevents
  a valid Universal implementation;
- **rejected**: intentionally unavailable in Universal mode.

No entry may be changed to **supported** without linking its tests in the same
change.

| Area | HPy Universal status | Initial requirement |
|---|---|---|
| Empty and constant-only modules | supported | Empty, documentation-only, pass-only, and supported assignment-only sources emit a valid `HPyModuleDef` plus `HPy_mod_exec` without a synthetic callable/type; a real constant-only `.hpy0` preserves docs and globals through binary-boundary checks and normal/Trace/Debug imports |
| Module-level functions | partial | Required untyped signatures plus scalar/list/tuple/dict and effectful defaults evaluated once in source-safe `HPy_mod_exec` order, positional-only/keyword-only parsing, linear statements, early/all-returning and continuing/nested conditionals, mixed terminating/continuing branches, conditional expressions, sequence unpacking (fixed/starred/nested) plus parallel/cascaded assignment, `while`/sequence-index `for`/`range`/`for-from` control including unpack targets, `assert`, local/`global` `del`, function-scope `locals()`/`vars()`/`dir()`, function-scope `globals()` plus module-scope `locals()`/`dir()` via owned `module.__dict__` (sorted keys), richer terminal `try`/`except` (pre-terminal try and handler assignments/expressions/deletions/if/while/for followed by return or explicit raise), return/raise from loops, and stable branch/loop local merges pass cleanup; qualified package-module names preserve the full runtime identity while exporting the leaf `HPyInit_*` symbol, and valid Unicode module-function/extension-method names retain their Python spelling while only private C symbols are encoded; both pass normal/Trace/Debug import; Python `__defaults__`/`__kwdefaults__` introspection, `except as`/else/finally/nested try, and relative/star imports remain blocked |
| Primitive Python values | supported | `None`, booleans, arbitrary-size ints, finite/overflow-infinite floats, imaginary/complex literals, Ellipsis via `ctx->h_Ellipsis`, f-strings (`!s`/`!r`/`!a` plus `__format__`/`HPy_Add`), walrus assignment to simple locals/module globals with owned `HPy_Dup`, all source Unicode forms including NUL and lone surrogates, and arbitrary bytes pass normal/debug execution; function Unicode/bytes/None/bool/int/float/imaginary literals are deduplicated in interpreter-owned module caches |
| Tuple/list/dict/set construction | partial | Empty, fixed-size, nested, multiplied, and generic-iterable-starred list/tuple plus dict literals pass cleanup; keyword/`**` merges reject duplicate keys with the public TypeError; list/dict comprehensions and sequence-safe inlined `list`/`any`/`all`/`dict` genexps over sequence-index iterables (literal or dynamic, including nested fors, filters, and unpack targets) use `ListType()`/`append` and `HPyDict_New`/`HPy_SetItem`; starred segments are normalized through the public ListType/TupleType context handles and concatenated in source order; recursively immutable function tuples use interpreter-owned deduplicated caches; HPy 0.9 lacks public set construction/add APIs and SetType (set comprehensions remain blocked), while set literals and true iterator-protocol loops remain blocked |
| Calls and keyword arguments | partial | Zero/one/multiple and generic-iterable-starred positional arguments, explicit and dynamic-mapping keywords, mixed calls, and attribute method calls through `HPy_CallMethod` (receiver as `args[0]`, no bound-method GetAttr) pass cleanup; `HPy_CallTupleDict` handles expanded calls, mapping keys are merged through public HPy operations with duplicate/non-mapping validation, and signatures accept required positional/keyword calls |
| Attributes and items | supported | Attribute/item and slice read, set, delete, and in-place mutation pass success/error cleanup with one-time target/bound evaluation |
| Arithmetic and comparisons | supported | All public HPy binary and in-place number APIs (including matrix multiply and power), unary `+`/`-`/`~`, value-preserving boolean operations, six rich comparisons, identity/membership, and short-circuiting cascades pass cleanup |
| Iteration | partial | Sequence-index `for` loops and list/dict comps use public `HPy_Length`/`HPy_GetItem_i` over literal or dynamic sequence expressions (including empty sequences) with break/continue/else, simple or unpacking targets, and Debug Mode cleanup. Counted `range` / `for-from` loops (and matching comps) use `HPy_ssize_t` C iteration plus `HPyLong_FromSsize_t` for untyped Python targets; typed C loop targets stay rejected. Sequence-safe inlined generator expressions for `list`/`any`/`all`/`dict` are supported; true GetIter/IterNext loops and real `yield` generators stay rejected on HPy 0.9; pure-type `__iter__`/`__next__` receive a versioned ABI diagnostic because HPy 0.9 exposes neither `HPy_tp_iter` nor `HPy_tp_iternext`; CPython `Py_tp_*` substitution is forbidden |
| Imports, globals, and builtins | partial | Absolute imports, `from` bindings, module assignments/overwrite, referenced functions, function-level global set/in-place/delete, dynamic module-to-builtins reads, exact missing-name errors, and external rebinding use interpreter-owned module attributes through `HPy_mod_exec`; normal/debug cleanup, retry after failed-loader collection, reload, concurrent import, process teardown, positive builtin fallback, and mutable subinterpreter-isolation gates pass; HPy 0.9 immediate retry without an explicit GC boundary is a documented upstream/loader gap (oracle keeps `gc.collect()`; GC-free retry is not a support claim), `HPyGlobal` storage is prohibited for mutable state, and relative/star imports, custom module `__getattr__` parity, while code-object caches remain rejected/planned |
| Exceptions | partial | Bare HPy context-provided builtin exception types and calls with zero, one, or multiple arbitrary supported positional payloads build an exact argument tuple; this preserves tuple payloads as one argument and source-ordered evaluation failures. Safe single Unicode uses `HPyErr_SetString`, NUL/lone-surrogate Unicode uses `HPyErr_SetObject`, and argless `MemoryError` uses `HPyErr_NoMemory`. Dynamically evaluated exception instances, subclasses, and positional/keyword constructor calls use public `HPy_Type`, `HPy_TypeCheck`, and `HPyType_IsSubtype`, preserve instance identity and constructor failures, and reject invalid operands. HPy 0.9 current-error matching supports a terminal linear `try` body ending in return/raise with direct/tuple-normalized builtin, multiple, or default clauses; after a match is cleared, handlers may run linear assignments, expressions, deletions, pass, supported `if`/`while`/`for`, and then return or explicitly raise. Failure labels preserve entry-owned handles/trackers, clean only try-created intermediates, propagate unmatched errors, and pass normal/Trace/Debug. `except as`, bare reraise, traceback, cause/chaining, `else`/`finally`, nesting, and observable handler state remain gated because HPy 0.9 has no public exception-triple/state API |
| `cdef class` pure HPy types | partial | Private classes use a pure native struct, `HPyType_HELPERS`, `HPyType_Spec`, `HPyType_FromSpec`, and interpreter-owned module publication with no `PyObject_HEAD`; valid Unicode class, method, property, argument, closure-capture, and public-field names remain intact at Python/HPy boundaries while only private generated C symbols are encoded; ordinary undecorated instance methods use `HPyDef_METH` and support type-owned side-effect-free positional/keyword-only defaults with inherited mutable identity, while slotless `__format__`, `__bytes__`, `__complex__`, `__round__`, and synchronous context-manager `__enter__`/`__exit__` are ordinary methods with exact source arities; user-written properties use `HPyDef_GET`, `HPyDef_SET`, or `HPyDef_GETSET`, preserve UTF-8/multiline/control-bearing docs through safe C literals, explicitly reject NUL-bearing docs that HPy's C-string field cannot represent, preserve missing-accessor behavior, and remain distinct from synthesized public-field descriptors; each type owns its defining module through a hidden interpreter-owned attribute, so ordinary and supported slot/property bodies (including conditional early returns for `__len__`/`__bool__`/`__hash__`/`__contains__`/`__call__`/getters) resolve dynamic globals, builtins, and constant caches without static state; `__cinit__` runs from `HPy_tp_new` in explicit base-to-derived order before `__init__`, with partial-object cleanup, nullary-base compatibility, inherited defaults, and callable construction; `__init__`, callable `__call__`, `__repr__`, `__str__`, `__len__`, overlapping mapping/sequence subscription and mutation, `__hash__`, `__bool__`, unary arithmetic, and integer/float/index conversions use their exact HPy slots; sequence indices cross the boundary through owned `HPyLong_FromSsize_t` handles and pass inherited normal/debug success and error cleanup; allocation pairs `HPy_tp_new`/`HPy_New` with HPy 0.9 vectorcall where required; initializer/call defaults use the same defining-type model; supported scalars have native storage; strict single inheritance from an earlier generated type in the same module uses `HPyType_SpecParam_Base`; HPy 0.9-missing iterator, attribute-hook, descriptor-hook, and async slots receive explicit versioned Universal-ABI diagnostics instead of CPython slot substitution; remaining native/builtin/extension-typed fields, weakrefs, unsupported special/decorated methods, and class visibility variants remain rejected pending their individual M5 gates |
| Definition docstrings | supported | Module, module-function, pure extension-type, ordinary extension-method, and property docs use their native `HPyModuleDef`, `HPyDef_METH`, `HPyType_Spec`, and get/set definition fields; UTF-8, multiline, quotes, backslashes, and controls round-trip through Cython's safe C-literal encoder in normal/Trace/Debug, while NUL-bearing docs receive an explicit diagnostic because the ABI exposes NUL-terminated C strings |
| Python-valued extension fields | partial | Private, public, and readonly generic `object` fields use `HPyField`; public/readonly descriptors use custom Universal `HPyDef_GETSET`/`HPyDef_GET` accessors because HPy 0.9 mutates `HPyMember_OBJECT` offsets and misreads fields when a second interpreter recreates the type; descriptors and methods use `Struct_AsStruct` plus `HPyField_Load`/`Store`, inherited Cython entries alias physical base storage, public deletion stores `None` and releases the old payload, generated traversal visits inherited and newly declared fields exactly once, inherited-only layouts receive a local traverse wrapper and `HPy_TPFLAGS_HAVE_GC`, and normal/debug self-cycle, base/derived-cycle collection, traverse-driven refcount deallocation, plus three-subinterpreter descriptor isolation pass |
| Native extension fields | partial | Plain/signed/unsigned byte, short, int, long, long long, `Py_ssize_t`, `float`/`double`/`long double`, char-backed `bint`, and non-external local scalar typedef chains use exact native storage; types with an exact HPy member kind use `HPyDef_MEMBER`, while `long double` uses Universal custom get/set descriptors instead of a mismatched double member; direct public/private reads/writes and C-semantic `+=`/`-=`/`*=`/`&=`/`|=`/`^=`/`<<=`/`>>=` pass checked conversion/narrowing behavior, readonly/deletion checks, cleanup, and exclusion from GC traversal; untyped-RHS `/=`/`//=`/`%=`/`**=` preserve Cython's Python-result path through exact HPy in-place APIs followed by checked native conversion; plain `char` preserves single-ASCII-string descriptor versus numeric direct-access semantics, `bint` distinguishes exact-bool descriptors from Cython truth-test writes, and `Py_ssize_t` uses checked platform-range conversion; future typed direct-C division/modulo/power directives remain planned, while external typedef and enum fields are explicitly rejected with ABI-layout diagnostics rather than guessed member kinds |
| Inheritance and slots | partial | A strict same-module, declaration-ordered single generated base passes embedded payload layout, `HPyType_SpecParam_Base`, direct inherited private-field access, explicit base-to-derived `__cinit__`, inherited methods/effective `__init__`/`__call__` wrappers and defaults, inherited-only GC traversal, cyclic GC, interpreter-owned base/module lookup, three-subinterpreter constructor/method/slot/finalizer state isolation, and normal/debug cleanup; value, length, mapping, hash, C-int boolean/membership, unary arithmetic, integer/float/index conversion, local/inherited/no-init call allocation, and six-way rich-comparison dispatch pass their exact HPy contracts; all 13 two-argument binary/reflected numeric families share their exact HPy slots through interpreter-owned marker dispatch, all 12 corresponding in-place families pass real normal/debug execution, and derived overrides merge inherited directions with runtime subtype priority; ternary `__pow__`/`__rpow__`/`__ipow__` use the exact power slots, accept Cython's two- or three-argument form, preserve optional-modulus semantics, and merge inherited/reflected directions; multiple, forward, cross-module, builtin-base, metaclass, iteration, and remaining slot families require individual gates |
| Instance dict/weakrefs/finalizers/freelists | partial | `__del__` uses `HPy_tp_finalize`; one-shot resurrection, second deallocation, `HPyErr_WriteUnraisable` error reporting, and normal/debug cleanup pass. Public and failed-`__cinit__` `HPyField` clearing is validated. HPy 0.9 has no public portable instance-dict or weakref layout/offset surface, so `__dict__` and `__weakref__` receive separate ABI diagnostics rather than CPython-only offsets; `__dealloc__` is explicitly gated because `HPy_tp_destroy` exposes raw storage without context/self handles; native-resource destroy hooks and freelists remain planned |
| Closures | partial | One-level nested `def` in the same module uses synthesized env/callable HPy extension types with `HPyField` captures (ADR 0005); sibling functions share the stable union of captures, capture-free functions retain an empty owned env, and outer reassignment updates shared fields; C-typed captures, nested-nested, defaults, `*args`/`**kwargs`, generators/`yield`, and decorated nested defs are rejected with actionable diagnostics |
| Generators | blocked | ADR 0006 defines the suspended-handle/resume model, but HPy 0.9 exposes neither the public iterator-next type slots required to publish a generator object nor the complete iterator/exception-state APIs needed for `yield from`, `send`, `throw`, `close`, and StopIteration values; top-level `yield`/`yield from` and real generator expressions fail with versioned diagnostics, while explicitly inlined sequence-safe consumers remain a non-generator partial surface |
| Coroutines/async generators | blocked | ADR 0007 defines independent await/cancellation/async-suspension ownership, but HPy 0.9 lacks the required public async protocol type slots and complete exception-state surface; top-level `async def`/`await` and async generators fail before CPython coroutine utilities can be selected |
| Buffer protocol producer | partial | Canonical Cython `Py_buffer` source syntax is accepted only for the validated writable one-dimensional fixed native-scalar or private positive compile-time-sized native C-array exporter contract and translated to public `HPy_buffer`, `HPy_bf_getbuffer`, and `HPy_bf_releasebuffer` output. All 13 enabled signed/unsigned integer and float format mappings compile for both layouts; object-owned `Py_ssize_t` shape/stride storage, an owned duplicated exporter handle, retained scalar/array views, writable `long`/`double`, four-element `long` array mutation, ordinary derived-type slot inheritance, Normal/Trace/Debug execution, and scalar-plus-array duplication failure are covered. Readonly exporters remain blocked because HPy 0.9 publishes no named writable-request flag; multidimensional/general array-field, auxiliary-allocation, and custom-release exporters remain rejected |
| Typed memoryviews | blocked | HPy 0.9 exposes no public buffer acquire/release consumer API; typed buffer/memoryview arguments are rejected immediately after declaration analysis, before CPython `View.MemoryView` utilities can enter the Universal pipeline |
| Fused types | planned | ADR 0009 requires neutral specialization descriptors, exact Cython dispatch/conversion parity, a pure-HPy callable/subscriptable dispatcher, and interpreter-owned signature metadata; fused `def`/`cpdef` currently fail with one diagnostic and never select CPython `__Pyx_FusedFunction`/PyCFunction machinery |
| `nogil` and parallelism | partial | ADR 0010 enables a strict slice: a non-empty `with nogil` body may contain discarded calls or Python local/global, attribute, item, or slice assignments from validated Python-independent external C functions declared `noexcept nogil` or exact signed `except -1 nogil`; literals become portable native constants and other supported scalar arguments, including attribute/item expressions, complete source-ordered HPy evaluation, checked conversion, and handle closure before the per-call `HPyThreadState` leaves execution, while used scalar results remain native until re-entry and are then boxed and assigned. Explicit non-empty `with gil` islands may run supported Python bodies between native intervals; implicit, conditional, and empty islands fail closed. The exact errno lane clears before the native call, snapshots before re-entry, and raises public-HPy `OSError` after re-entry or deterministic `RuntimeError` when errno is missing. The maintained linked normal/Trace/Debug oracle proves native success, conversion failure without native entry, statement ordering, each supported retained-result target, GIL-island callback success/failure, and held/released/discarded errno failures. ADR 0011 defines a neutral parallel plan and native-only worker path, but HPy 0.9 has no public arbitrary-worker attach/error-transport API, so `prange` and `parallel()` fail closed before CPython thread-state machinery. Compound/destructuring result targets, other native failure protocols, exception reacquisition, callbacks crossing the C boundary, long-lived nested transitions, OpenMP execution, synchronization, and free-threading remain independently gated |
| C++ output | planned | Exception/RAII cleanup correctness |
| Code objects and function introspection | blocked | HPy 0.9 exposes no public code-object constructor or `CodeType` context handle, and HPy module methods are not Python function objects; no CPython emulation is permitted in Universal mode |
| Python-independent external C | partial | Concrete injection-safe headers and direct standard C scalar parameters/results are supported with source-ordered HPy conversions and checked narrowing; discarded zero/scalar-argument calls and scalar results assigned to Python local/global, attribute, item, or slice targets may use ADR 0010's handle-free execution-state interval after all argument conversions complete. Exact signed `except -1` adds the documented errno→`OSError` contract for held and nogil calls. The maintained linked-library example passes normal/Trace/Debug, source/binary audits, wheel installation, overflow behavior, argumentless/scalar native probes, conversion-failure non-entry, statement ordering, retained-result targets, errno failures, and missing-errno diagnostics. `Python.h`, inline declarations, external typedefs, pointers, aggregates, variables, variadics, optional parameters, Python-inspecting exception checks, and non-`-1`/unsigned sentinels are rejected; pointer/buffer ownership, compound/destructuring `nogil` result targets, and other native error protocols remain planned |
| `cpython.*` cimports | rejected | Actionable Universal-mode diagnostic |
| `PyObject *` interoperability | rejected | Actionable Universal-mode diagnostic |
| HPy legacy conversions | rejected | Actionable Universal-mode diagnostic |
| CPython-only third-party C APIs | blocked | Dependency must expose an HPy API |
| NumPy C-API | blocked | Requires a validated Universal path |
| HPy Hybrid fallback | rejected | Must be an explicit future mode |
| Direct non-setuptools build | partial | The version-1 plan/API/CLI discovers the selected HPy toolchain, enforces Universal definitions, forbid-header ordering, helper static/source runtime inputs, `.hpy0` suffix and MSVC export rules, refuses unsafe reuse, audits source/binary boundaries, and passes normal/Debug public-loader execution. Run 29685285138 is green on Linux GCC/Clang, Linux ARM64 GCC, macOS Intel/ARM64 Clang, and Windows MSVC; packaging/import stubs are separate |
| CMake/Meson native builds | partial | Installed `ahpy_build_config` renders one selected-interpreter Universal contract; maintained CMake `MODULE` and Meson `shared_module` examples pass source/binary audits plus normal/Debug loading locally on macOS ARM64 and hosted on Linux x64 in run 29685285138. | scikit-build-core packaging | partial | The exact `aHPy-compiler` frontend, HPy 0.9, setuptools 83.0.0, scikit-build-core, CMake, and Ninja are resolved from a closed hashed wheelhouse; the isolated CMake wheel installs and imports in normal/Debug locally and on hosted Linux in run 29685285138. Its CPython-specific tag is not a portable Universal wheel claim, and cross-compilation evidence remains open |
| Frontend sdist and onboarding | partial | A clean `aHPy-compiler` sdist passes member safety/completeness and exact-identity audits; its no-index wheel installs with exact HPy 0.9/setuptools 83.0.0 in a new venv; the maintained PEP 517 example and frontend each pass uninstall/absence/reinstall plus normal/Debug execution locally and on hosted Linux in run 29685285138. ## Target validation dimensions

The final supported version set will follow the intersection of validated
Cython, HPy, and interpreter versions rather than an untested numerical range.

| Dimension | Required lanes |
|---|---|
| Runtime backend | CPython regression, HPy CPython ABI, HPy Universal ABI |
| Interpreter | CPython 3.11 stable baseline; pinned PyPy/GraalPy early warnings until green |
| HPy | 0.9 release and one pinned validated development revision |
| OS | Linux x86-64/ARM64, macOS Intel/ARM, Windows x64 |
| Compiler | GCC, Clang, MSVC |
| Runtime mode | release, HPy debug, HPy trace |
| Analysis | forbidden symbols, ASan, UBSan, leak checks |

The stable workflow supports its CPython 3.11/HPy 0.9 baseline on Linux
x86-64/ARM64, macOS Intel/ARM64, and Windows x64 with GCC, Clang, and MSVC.
All six required jobs first went green in hosted run 29685285138 and were
revalidated at implementation commit `20e401ca7` in hosted run 29900694746.
Local macOS ARM64 validation also passes HPy 0.9.0 on Python 3.11 in
release, Trace, and Debug modes. Pinned HPy development commit
`b57a33c1cec766a1cc3e89f6fd1e2eff73ba9381` passes the same gate on Python
3.11; its Python 3.14.6 semantic run currently terminates with `SIGSEGV` and is
therefore an allowed-failure early warning. Exact pins and runner state are in
`tests/ahpy/hpy-versions.toml` and `validation-matrix.md`; the
[PRD-5 audit](audits/prd5-portability-native-memory.md) records the minimal
closure and handwritten reproducers; only publication of the prepared upstream
HPy issue report remains an external PRD-5 action.

Schedule/manual-only nightlies are deliberately outside that support claim.
One uses the moving CPython `3.15-dev` prerelease with stable HPy 0.9; the other
uses CPython 3.11 with HPy's official `master` branch. Both are allowed-failure,
run independently of the full-commit development lane, and upload actual
interpreter/package/VCS provenance. A green or red nightly is early warning
only and cannot promote an interpreter or HPy revision to supported. Manual
run 29906185775 records CPython 3.15.0-beta.4 failing while building HPy 0.9
before aHPy executes and HPy master resolving to the pinned
`b57a33c1cec766a1cc3e89f6fd1e2eff73ba9381` commit before an unbounded
optimized build hung. Both runtime steps now use the validated `-O0` semantic
profile and are bounded to 30 minutes. Manual run 29912162645, job 88897432348,
then recorded the first bounded green HPy-master execution on CPython 3.11; the
generated runtime completed in 19 seconds. The CPython 3.15/HPy 0.9 lane still
fails in HPy's own build before aHPy executes. Neither result changes support.

The baseline Cython revision is
`b99cb0e3b5425e11414cadd24168a6cc850e8000` from 2026-07-13.
