# aHPy support matrix

Status values:

- **planned**: designed but not implemented;
- **in progress**: implementation exists but has not passed its exit gate;
- **supported**: all required tests and audits pass;
- **partial**: a documented subset passes and unsupported cases are diagnosed;
- **blocked**: an external API or unresolved design issue prevents correctness;
- **rejected**: intentionally unavailable in this ABI mode.

No entry may be changed to **supported** without linking its tests in the same
change.

| Area | HPy Universal status | Initial requirement |
|---|---|---|
| Module-level functions | partial | Required untyped signatures plus scalar/list/tuple/dict and effectful defaults evaluated once in source-safe `HPy_mod_exec` order, positional-only/keyword-only parsing, linear statements, early/all-returning and continuing/nested conditionals, mixed terminating/continuing branches, conditional expressions, sequence unpacking (fixed/starred/nested) plus parallel/cascaded assignment, `while`/sequence-index `for`/`range`/`for-from` control including unpack targets, `assert`, local/`global` `del`, function-scope `locals()`/`vars()`/`dir()`, function-scope `globals()` plus module-scope `locals()`/`dir()` via owned `module.__dict__` (sorted keys), richer terminal `try`/`except` (pre-terminal if/while/for; bootstrap handler returns after clear), and return/raise from loops, and stable branch/loop local merges pass cleanup; Python `__defaults__`/`__kwdefaults__` introspection, `except as`/else/finally/nested try, and relative/star imports remain blocked |
| Primitive Python values | supported | `None`, booleans, arbitrary-size ints, finite/overflow-infinite floats, imaginary/complex literals, Ellipsis via `ctx->h_Ellipsis`, f-strings (`!s`/`!r`/`!a` plus `__format__`/`HPy_Add`), walrus assignment to simple locals/module globals with owned `HPy_Dup`, all source Unicode forms including NUL and lone surrogates, and arbitrary bytes pass normal/debug execution; function Unicode/bytes/None/bool/int/float/imaginary literals are deduplicated in interpreter-owned module caches |
| Tuple/list/dict/set construction | partial | Empty, fixed-size, nested, multiplied, and generic-iterable-starred list/tuple plus dict literals pass cleanup; keyword/`**` merges reject duplicate keys with the public TypeError; list/dict comprehensions and sequence-safe inlined `list`/`any`/`all`/`dict` genexps over sequence-index iterables (literal or dynamic, including nested fors, filters, and unpack targets) use `ListType()`/`append` and `HPyDict_New`/`HPy_SetItem`; starred segments are normalized through the public ListType/TupleType context handles and concatenated in source order; recursively immutable function tuples use interpreter-owned deduplicated caches; HPy 0.9 lacks public set construction/add APIs and SetType (set comprehensions remain blocked), while set literals and true iterator-protocol loops remain blocked |
| Calls and keyword arguments | partial | Zero/one/multiple and generic-iterable-starred positional arguments, explicit and dynamic-mapping keywords, mixed calls, and attribute method calls through `HPy_CallMethod` (receiver as `args[0]`, no bound-method GetAttr) pass cleanup; `HPy_CallTupleDict` handles expanded calls, mapping keys are merged through public HPy operations with duplicate/non-mapping validation, and signatures accept required positional/keyword calls |
| Attributes and items | supported | Attribute/item and slice read, set, delete, and in-place mutation pass success/error cleanup with one-time target/bound evaluation |
| Arithmetic and comparisons | supported | All public HPy binary and in-place number APIs (including matrix multiply and power), unary `+`/`-`/`~`, value-preserving boolean operations, six rich comparisons, identity/membership, and short-circuiting cascades pass cleanup |
| Iteration | partial | Sequence-index `for` loops and list/dict comps use public `HPy_Length`/`HPy_GetItem_i` over literal or dynamic sequence expressions (including empty sequences) with break/continue/else, simple or unpacking targets, and Debug Mode cleanup. Counted `range` / `for-from` loops (and matching comps) use `HPy_ssize_t` C iteration plus `HPyLong_FromSsize_t` for untyped Python targets; typed C loop targets stay rejected. Sequence-safe inlined generator expressions for `list`/`any`/`all`/`dict` are supported; true GetIter/IterNext loops and real `yield` generators stay rejected on HPy 0.9; pure-type `__iter__`/`__next__` receive a versioned ABI diagnostic because HPy 0.9 exposes neither `HPy_tp_iter` nor `HPy_tp_iternext`; CPython `Py_tp_*` substitution is forbidden |
| Imports, globals, and builtins | partial | Absolute imports, `from` bindings, module assignments/overwrite, referenced functions, function-level global set/in-place/delete, dynamic module-to-builtins reads, exact missing-name errors, and external rebinding use interpreter-owned module attributes through `HPy_mod_exec`; normal/debug cleanup, retry after failed-loader collection, reload, concurrent import, process teardown, positive builtin fallback, and mutable subinterpreter-isolation gates pass; HPy 0.9 immediate retry without an explicit GC boundary is intermittently unstable, `HPyGlobal` storage is prohibited for mutable state, and relative/star imports, custom module `__getattr__` parity, while code-object caches remain rejected/planned |
| Exceptions | partial | Bare HPy context-provided builtin exception types and calls with zero, one, or multiple arbitrary supported positional payloads build an exact argument tuple; this preserves tuple payloads as one argument and source-ordered evaluation failures. Safe single Unicode uses `HPyErr_SetString`, NUL/lone-surrogate Unicode uses `HPyErr_SetObject`, and argless `MemoryError` uses `HPyErr_NoMemory`. Dynamically evaluated exception instances, subclasses, and positional/keyword constructor calls use public `HPy_Type`, `HPy_TypeCheck`, and `HPyType_IsSubtype`, preserve instance identity and constructor failures, and reject invalid operands. HPy 0.9 current-error matching now supports a terminal linear `try` body ending in return/raise with direct/tuple-normalized builtin, multiple, or default clauses whose handlers return side-effect-free literals; failure labels preserve entry-owned handles/trackers, clean only try-created intermediates, clear matched errors, propagate unmatched errors, and pass normal/Trace/Debug. General handler bodies, `except as`, reraise, traceback, cause/chaining, `else`/`finally`, nesting, and observable handler state remain gated because HPy 0.9 has no public exception-triple/state API |
| `cdef class` pure HPy types | partial | Private classes use a pure native struct, `HPyType_HELPERS`, `HPyType_Spec`, `HPyType_FromSpec`, and interpreter-owned module publication with no `PyObject_HEAD`; ordinary undecorated instance methods use `HPyDef_METH` and support type-owned side-effect-free positional/keyword-only defaults with inherited mutable identity, while slotless `__format__` is an ordinary method (`HPyFunc_O` for its positional-only spelling); user-written properties use `HPyDef_GET`, `HPyDef_SET`, or `HPyDef_GETSET`, preserve docs and missing-accessor behavior, and remain distinct from synthesized public-field descriptors; each type owns its defining module through a hidden interpreter-owned attribute, so ordinary and supported slot/property bodies (including conditional early returns for `__len__`/`__bool__`/`__hash__`/`__contains__`/`__call__`/getters) resolve dynamic globals, builtins, and constant caches without static state; `__cinit__` runs from `HPy_tp_new` in explicit base-to-derived order before `__init__`, with partial-object cleanup, nullary-base compatibility, inherited defaults, and callable construction; `__init__`, callable `__call__`, `__repr__`, `__str__`, `__len__`, overlapping mapping/sequence subscription and mutation, `__hash__`, `__bool__`, unary arithmetic, and integer/float/index conversions use their exact HPy slots; sequence indices cross the boundary through owned `HPyLong_FromSsize_t` handles and pass inherited normal/debug success and error cleanup; allocation pairs `HPy_tp_new`/`HPy_New` with HPy 0.9 vectorcall where required; initializer/call defaults use the same defining-type model; supported scalars have native storage; strict single inheritance from an earlier generated type in the same module uses `HPyType_SpecParam_Base`; HPy 0.9-missing iterator, attribute-hook, descriptor-hook, and async slots receive explicit versioned Universal-ABI diagnostics instead of CPython slot substitution; remaining native/builtin/extension-typed fields, weakrefs, unsupported special/decorated methods, and class visibility variants remain rejected pending their individual M5 gates |
| Python-valued extension fields | partial | Private, public, and readonly generic `object` fields use `HPyField`; public/readonly descriptors use custom Universal `HPyDef_GETSET`/`HPyDef_GET` accessors because HPy 0.9 mutates `HPyMember_OBJECT` offsets and misreads fields when a second interpreter recreates the type; descriptors and methods use `Struct_AsStruct` plus `HPyField_Load`/`Store`, inherited Cython entries alias physical base storage, public deletion stores `None` and releases the old payload, generated traversal visits inherited and newly declared fields exactly once, inherited-only layouts receive a local traverse wrapper and `HPy_TPFLAGS_HAVE_GC`, and normal/debug self-cycle, base/derived-cycle collection, traverse-driven refcount deallocation, plus three-subinterpreter descriptor isolation pass |
| Native extension fields | partial | Plain/signed/unsigned byte, short, int, long, long long, `Py_ssize_t`, `float`/`double`/`long double`, char-backed `bint`, and non-external local scalar typedef chains use exact native storage; types with an exact HPy member kind use `HPyDef_MEMBER`, while `long double` uses Universal custom get/set descriptors instead of a mismatched double member; direct public/private reads/writes and C-semantic `+=`/`-=`/`*=`/`&=`/`|=`/`^=`/`<<=`/`>>=` pass checked conversion/narrowing behavior, readonly/deletion checks, cleanup, and exclusion from GC traversal; untyped-RHS `/=`/`//=`/`%=`/`**=` preserve Cython's Python-result path through exact HPy in-place APIs followed by checked native conversion; plain `char` preserves single-ASCII-string descriptor versus numeric direct-access semantics, `bint` distinguishes exact-bool descriptors from Cython truth-test writes, and `Py_ssize_t` uses checked platform-range conversion; future typed direct-C division/modulo/power directives remain planned, while external typedef and enum fields are explicitly rejected with ABI-layout diagnostics rather than guessed member kinds |
| Inheritance and slots | partial | A strict same-module, declaration-ordered single generated base passes embedded payload layout, `HPyType_SpecParam_Base`, direct inherited private-field access, explicit base-to-derived `__cinit__`, inherited methods/effective `__init__`/`__call__` wrappers and defaults, inherited-only GC traversal, cyclic GC, interpreter-owned base/module lookup, three-subinterpreter constructor/method/slot/finalizer state isolation, and normal/debug cleanup; value, length, mapping, hash, C-int boolean/membership, unary arithmetic, integer/float/index conversion, local/inherited/no-init call allocation, and six-way rich-comparison dispatch pass their exact HPy contracts; all 13 two-argument binary/reflected numeric families share their exact HPy slots through interpreter-owned marker dispatch, all 12 corresponding in-place families pass real normal/debug execution, and derived overrides merge inherited directions with runtime subtype priority; ternary `__pow__`/`__rpow__`/`__ipow__` use the exact power slots, accept Cython's two- or three-argument form, preserve optional-modulus semantics, and merge inherited/reflected directions; multiple, forward, cross-module, builtin-base, metaclass, iteration, and remaining slot families require individual gates |
| Instance dict/weakrefs/finalizers/freelists | partial | `__del__` uses `HPy_tp_finalize`; one-shot resurrection, second deallocation, `HPyErr_WriteUnraisable` error reporting, and normal/debug cleanup pass. Public and failed-`__cinit__` `HPyField` clearing is validated. HPy 0.9 has no public portable instance-dict or weakref layout/offset surface, so `__dict__` and `__weakref__` receive separate ABI diagnostics rather than CPython-only offsets; `__dealloc__` is explicitly gated because `HPy_tp_destroy` exposes raw storage without context/self handles; native-resource destroy hooks and freelists remain planned |
| Closures | planned | Owned captured-handle model |
| Generators/coroutines | planned | Context and suspended-handle lifetime |
| Buffer protocol | planned | HPy_buffer lifecycle |
| Typed memoryviews | planned | Utility-type port and buffer support |
| Fused types | planned | Specialization parity |
| `nogil` and parallelism | planned | HPy leave/enter execution semantics |
| C++ output | planned | Exception/RAII cleanup correctness |

## Target validation dimensions

The final supported version set will follow the intersection of validated
Cython, HPy, and interpreter versions rather than an untested numerical range.

| Dimension | Required lanes |
|---|---|
| Runtime backend | CPython regression, HPy CPython ABI, HPy Universal ABI |
| Interpreter | Supported CPython, PyPy, and GraalPy releases |
| HPy | 0.9 release and one pinned validated development revision |
| OS | Linux x86-64/ARM64, macOS Intel/ARM, Windows x64 |
| Compiler | GCC, Clang, MSVC |
| Runtime mode | release, HPy debug, HPy trace |
| Analysis | forbidden symbols, ASan, UBSan, leak checks |

The initial stable workflow is declared for Linux x86-64/ARM64, macOS
Intel/ARM64, and Windows x64 with GCC, Clang, and MSVC. These entries remain
validation targets—not supported-platform claims—until their first hosted runs
are green. Local macOS ARM64 validation passes HPy 0.9.0 on Python 3.11 in
release, Trace, and Debug modes. Pinned HPy development commit
`b57a33c1cec766a1cc3e89f6fd1e2eff73ba9381` passes the same gate on Python
3.11; its Python 3.14.6 semantic run currently terminates with `SIGSEGV` and is
therefore an allowed-failure early warning. Exact pins and runner state are in
`tests/ahpy/hpy-versions.toml` and `validation-matrix.md`.

Schedule/manual-only nightlies are deliberately outside that support claim.
One uses the moving CPython `3.15-dev` prerelease with stable HPy 0.9; the other
uses CPython 3.11 with HPy's official `master` branch. Both are allowed-failure,
run independently of the full-commit development lane, and upload actual
interpreter/package/VCS provenance. A green or red nightly is early warning
only and cannot promote an interpreter or HPy revision to supported.

The baseline Cython revision is
`b99cb0e3b5425e11414cadd24168a6cc850e8000` from 2026-07-13.
