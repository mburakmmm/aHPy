# Isolated PEP 517 builds

Use the `aHPy-compiler` distribution and `ahpy_build_backend` in an extension
project's `pyproject.toml`:

```toml
[build-system]
requires = [
    "aHPy-compiler==3.3.0.1.dev0",
    "hpy==0.9.0",
    "setuptools==83.0.0",
]
build-backend = "ahpy_build_backend"
```

The backend validates the exact aHPy frontend and installs the packaged HPy
0.9 loader compatibility hook before delegating each build hook. This permits
the security-patched setuptools pin without adding `pkg_resources` back to the
runtime environment; an unrecognized partial HPy loader template fails closed.
The frontend wheel additionally advertises the same callable through the
`cython.runtime_backend_build_hooks` entry-point group. Direct installed
`cythonize()` users therefore receive the preparation automatically; missing,
duplicate, unloadable, or conflicting providers fail closed.

The exact frontend pin is mandatory. Upstream `Cython` does not contain this
repository's Universal backend, while the PyPI distribution named `ahpy` is an
unrelated project. The aHPy compiler distribution is not published yet, so
users must build or obtain the reviewed `aHPy-compiler` wheel from the project
owner's trusted artifact source. Do not replace the requirement with `ahpy`.

The backend verifies its own distribution identity/version and forces
`--hpy-abi=universal` for setuptools. The project's `setup.py` must still pass
extensions produced by `cythonize(..., runtime_backend="hpy-universal")` as
`hpy_ext_modules`; the maintained complete example is
[`examples/ahpy_pep517`](../../examples/ahpy_pep517/README.md).

From this repository, run the end-to-end isolation gate with:

```console
.venv-hpy09/bin/python Tools/ahpy/pep517_integration.py \
    --python .venv-hpy09/bin/python \
    --output /tmp/ahpy-pep517.json
```

The command needs package-index access only to materialize the exact HPy 0.9
and exact setuptools 83.0.0 wheels in a temporary wheelhouse; HPy may be built
from its sdist when no platform wheel exists. It builds the
frontend wheel from a clean copy, disables index access for the separate
isolated example resolver, audits source/binary boundaries, installs the result
into an empty target, and runs normal plus HPy Debug semantics. The JSON report
records hashes for all three build-dependency wheels.

HPy 0.9 currently gives the example wheel a host-specific CPython tag. This
path proves isolation and provenance, not cross-interpreter wheel portability;
ADR 0004 remains the wheel-tag policy.
